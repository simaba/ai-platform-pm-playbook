# Public Release Checklist

Complete this checklist before making the repository public or publishing a versioned release.

## Content safety

- [ ] Confirm all templates, examples, and worked examples are fictional, generic, or fully sanitized.
- [ ] Confirm no real product roadmaps, internal strategy material, vendor evaluations, pricing, contract terms, negotiation material, or stakeholder information is present.
- [ ] Confirm no private platform architecture, system prompts, evaluation results, launch gates, incidents, unreleased feature plans, security details, or data-access patterns are present.
- [ ] Confirm no employer, customer, vendor, supplier, colleague, or other identifiable stakeholder information is included.
- [ ] Confirm no API keys, tokens, credentials, connector details, account identifiers, private paths, or private email addresses are present.

## GitHub surfaces

- [ ] Review all branches and the complete git history for material that should not become public.
- [ ] Review issues, pull requests, comments, Actions logs and artifacts, releases, tags, attachments, and repository metadata.

## Quality baseline

- [ ] Confirm the README, templates, frameworks, and worked example agree on the current repository scope and implemented behavior.
- [ ] Confirm no framework implies a universal threshold, legal interpretation, required vendor decision, or guaranteed behavioral result.
- [ ] Confirm the README does not imply procurement, legal, security, privacy, compliance, or investment advice.
- [ ] Confirm CI and links pass on the intended release commit.
- [ ] Confirm the license, security policy, contribution guidance, and quick-start guidance are accurate and usable.

## Release practice

- [ ] Search the repository for company, product, vendor, customer, roadmap, contract, pricing, email, credential, token, key, and private-path terms before release.
- [ ] Create a draft GitHub Release first and review all notes and assets before publishing.

This checklist does not replace employer, legal, security, privacy, procurement, or compliance review.
