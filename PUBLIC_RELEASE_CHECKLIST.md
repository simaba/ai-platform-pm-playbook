# Public Release Checklist

Use this checklist before changing the repository visibility to public.

## Required before publishing

- [ ] Confirm all examples are fictional, generic, or fully sanitized.
- [ ] Confirm no real product roadmaps, internal strategy documents, vendor evaluations, pricing details, contract terms, or negotiation material is committed.
- [ ] Confirm no employer, customer, vendor, supplier, colleague, or stakeholder information is included.
- [ ] Confirm no private platform architecture, system prompts, evaluation results, launch gates, or incident details are included.
- [ ] Confirm no unreleased feature plans, internal PRDs, security details, or data-access patterns are included.
- [ ] Confirm no API keys, tokens, credentials, connector details, account identifiers, private paths, or emails are present.
- [ ] Confirm the README does not imply procurement, legal, security, privacy, or investment advice.
- [ ] Confirm the license, README, and quick-start guidance are accurate.

## Recommended before promotion

- [ ] Add one fictional PRD template and worked example.
- [ ] Add one evaluation-plan template that treats evals as product requirements.
- [ ] Add one build-vs-buy framework with assumptions and caveats.
- [ ] Add folder-level READMEs.
- [ ] Clearly separate evergreen frameworks from opinionated essays.

## Final manual review

Before publishing, search the repo for company names, product names, vendor names, customer names, roadmap details, emails, tokens, keys, private paths, and real platform artifacts.

This checklist is a publication aid, not a privacy, legal, procurement, or security guarantee.
